# Research sources & methodology

This catalogue was built by cross-referencing multiple discovery sources rather than copying any single list.

## Primary discovery sources

- [Open Source Games List (OSGL)](https://github.com/Trilarion/opensourcegames) — broad catalogue of open-source games, tools, frameworks and libraries.
- [Awesome Open Source Games](https://github.com/michelpereira/awesome-open-source-games) — GitHub-oriented discovery list covering native, browser and mobile projects.
- [Awesome Game Remakes](https://github.com/radek-sprta/awesome-game-remakes) — useful for actively maintained reimplementations and source ports.
- [Games on GitHub](https://github.com/leereilly/games) — historical discovery source; the original project is archived, so entries were not treated as proof of current maintenance.
- GitHub search and topic pages for direct discovery of maintained repositories.

## Verification approach

1. Discover candidate projects from the sources above and current GitHub search results.
2. Prefer canonical upstream repositories over forks and mirrors.
3. Keep standalone open-source games in the game catalogue.
4. Put engine/source-port/reimplementation projects in their dedicated section when they are primarily compatibility or preservation projects.
5. Flag asset-dependent reimplementations so readers do not confuse open code with open game data.
6. Exclude obvious duplicates, search-result pages, generic topic pages, and non-game development resources from the game catalogue.
7. Use short original descriptions instead of copying upstream README text.

## Important limitation

A public repository does not automatically mean that every asset, binary, soundtrack, trademark, or game-data file is freely redistributable. Licensing claims should always be checked against the upstream repository before reuse.
